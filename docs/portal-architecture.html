Mash Events — How the Portal Works

one Next.js deploy · many event websites · one admin console

One platform, many events

  • • One deploy on Vercel, one Postgres — every event shares the engine
  • • Hostname picks the org: each org gets its own subdomain
  • • Each event's pages are custom code (sites/<org>/<event>/), no CMS
  • • proxy.ts resolves host → org → event before any code runs

Isolation by design

  • • The event id is in every admin URL and API call — never in the session
  • • Row-level security is pinned to one event per request
  • • Join links are signed per event (HKDF) — event A's token fails on event B
  • • Every admin action lands in an append-only audit_log

The registration pipeline

  • • Register → acknowledgement email (queued, not sent inline)
  • • Review: manual confirm/waitlist/reject, or auto-confirm per event
  • • Confirmation email carries the personal webinar join link
  • • A cron drains the queue every 5 minutes; Resend delivers
